# PAXVEIL: проверка зависимостей через Telegram

PAXVEIL сохраняет состав Python-проекта, проверяет зависимости по публичным источникам и помогает выбрать следующий шаг: разобрать находку, сравнить обновления или включить повторную проверку. Telegram-бот и веб-интерфейс работают с одним API и разграничивают доступ по владельцу.

Состояние на **21 октября 2026 года**: приложение запускается на компьютере владельца без платного хостинга. [@PAXVEIL_Bot](https://t.me/PAXVEIL_Bot) доступен, пока работают компьютер, сеть и сервисы. Публикация исходников на GitHub и внешний CI пока не завершены.

## Зачем нужен проект

Проверка зависимостей быстро теряет актуальность после одного запуска. Новая запись об уязвимости может появиться позже, одна проблема может иметь несколько идентификаторов, а обновление пакета меняет ограничения его зависимостей.

PAXVEIL объединяет сохранённый состав проекта, источники, историю проверок, варианты обновления и уведомления. Пользователь может вернуться к отчёту в Telegram, выяснить, какие его проекты затрагивает CVE, и сравнить проверенные по метаданным версии. Такой сценарий полезен для небольшого Python-проекта, которому нужен доступ к результатам без отдельной панели управления на телефоне.

Проект не определяет достижимость уязвимого кода и не подтверждает совместимость приложения после обновления. Метрики экономии времени и количество внешних пользователей пока не измерялись.

## Решения, которые можно проверить

| Задача | Реализация | Доказательство |
| --- | --- | --- |
| Сохранить происхождение результата | Датированные источники, хеши публичных снимков, неизменяемые отчёты и явные ошибки источников | [Отчёты анализа](CORE_VALIDATION.json) |
| Не потерять фоновое задание | PostgreSQL-очередь, срок владения, повторы и токен обработки | [Проверка PostgreSQL](POSTGRES_CONCURRENCY_VALIDATION.json) |
| Разделить данные пользователей | Сессии, проверка владельца объектов, одноразовая привязка Telegram | [Итоги тестов](TEST_RESULTS.md) |
| Ограничить расход ресурсов | Общие счётчики запросов, квоты аккаунта, очистка истории и ограниченный кеш | [Лимиты](PUBLIC_RESOURCES.md), [кеш](PUBLIC_CACHE.md) |
| Восстановить данные | Закрытая резервная копия и восстановление в отдельную БД со сверкой всех таблиц | [Проверка восстановления](BACKUP_VALIDATION.json) |
| Объяснить обновление | Реальные релизы PyPI, разрешение метаданных uv и повторный запрос OSV | [Core/FixLab](CORE.md) |

В тестовом прогоне PostgreSQL восемь потоков отправили 24 запроса на одну проверку и получили одно задание. Для 24 ожидающих заданий сохранились 24 разных права обработки. Проверены восстановление после истечения срока, отказ устаревшему worker, удаление аккаунта во время обработки и одновременное сохранение общего справочника. Общий лимит допустил ровно 11 из 64 запросов и восстановился в следующем временном окне. Рабочая БД не менялась: проверка использовала отдельную временную базу.

## Интерфейс и первый запуск

Первое действие в боте: `/example`. Пользователь получает файл с `requests==2.31.0` и запускает обычную проверку по текущим источникам. Готового ответа в примере нет, пакеты не устанавливаются. Через `/environment` выбирается окружение новых проектов, через `/privacy` доступны правила хранения и действия с данными.

Веб-приложение использует геометрический знак P, светлую и тёмную темы, синий акцент и адаптивную навигацию. 21 октября пройдены 20 браузерных проверок: загрузка примера и отмена, фильтры, продолжение FixLab, открытие сохранённой проверки по ссылке с перезагрузкой и возврат к последней. Черновик настроек владельца сохраняется при переходах, ошибка тихих часов показана у поля и переводит фокус на недостающее время. На мобильном экране содержимое шириной 375 пикселей не выходит за границы; шапка остаётся доступной, Escape возвращает фокус, выбор текущего раздела и расширение окна закрывают меню. [Результаты и скриншоты](USABILITY_VALIDATION.json), [оформление](DESIGN_REVIEW.md).

## Результаты

21 октября backend прошёл **178 тестов**. Две проверки внешних источников намеренно пропущены без включения сетевого режима; одно предупреждение относится к адаптеру Starlette/httpx. TypeScript и сборка frontend прошли.

В браузере новый проект с requests 2.31.0 прошёл настоящую проверку примерно за четыре секунды: получены три находки и показаны пять источников. Balanced и Maximum Coverage предложили requests 2.34.2; проверка предложенного состава не выявила известных находок. Minimal Change сообщил о недостатке данных. Запущенный FixLab сохранился при переходе на другую страницу и после перезагрузки.

В более раннем живом сканировании пяти закреплённых зависимостей получено 12 находок после объединения идентификаторов одной уязвимости. Balanced и Maximum Coverage разрешили пять пакетов; повторный запрос OSV для предложенных версий не выявил известных находок. Minimal Change сообщил об отсутствии подходящего предложения. Проверка CVE подтвердила `CVE-2024-35195` для `requests==2.31.0`. Это результаты конкретных версий и дат, а не обещание безопасности любого проекта.

21 октября свежая резервная копия размером 87 355 байт восстановилась в отдельную БД: совпали отпечатки 20 таблиц и 251 строки. Проверка локального супервизора прошла все 19 пунктов. Подтверждено EFS-шифрование выбранных локальных данных, журналов, закрытых копий и файла секретов. [Текущее окружение](CURRENT_RUNTIME_VALIDATION.json).

В тот же день в 13:54:43 UTC официальный Telegram API подтвердил @PAXVEIL_Bot, 12 команд в основном и русском списках и отсутствие webhook. Перед этим наблюдался сетевой сбой, после которого доступ восстановился. Более ранние ответы `/start`, `/privacy`, `/environment`, `/projects` подтвердил владелец в клиенте. Клиентские проверки файла, отчёта, FixLab, привязки и доставки Watch ещё нужно завершить.

## Демонстрация за несколько минут

1. Открыть бота, отправить `/example` и запустить проверку примера.
2. Показать находки, дату источников и ограничения отчёта; скачать JSON.
3. Запустить FixLab и сравнить предлагаемые версии. Указать, что после обновления нужны тесты самого приложения.
4. Выполнить `/fire CVE-2024-35195` и показать совпадение с сохранённым составом.
5. Включить Watch, сохранить настройки уведомлений и затем отключить его.
6. При показе браузера открыть отдельную проверку из истории, отфильтровать находки и показать мобильный экран.

Демонстрация требует работающего приложения и доступных источников. Не выдавайте тестовые события Watch за настоящую эксплуатацию. Не включайте в запись секреты, идентификаторы пользователей, частные файлы или резервные копии.

## Стек

Python 3.11, FastAPI, SQLAlchemy, Alembic, PostgreSQL, httpx, uv и aiogram; Next.js, React и TypeScript. Для выбранного запуска достаточно PostgreSQL и отдельных процессов приложения. Подготовлены Compose и GitHub Actions; их внешний запуск пока не подтверждён.


При публикации нужно проверить состав публичных файлов и сохранить границы выполненной приёмки. Открытая лицензия пока не включена; её выбор отделён от публикации репозитория. Полный запуск с чистого окружения и Docker ещё не проверены. [Архитектура](ARCHITECTURE.md) и [развёртывание](DEPLOYMENT.md) содержат детали.
