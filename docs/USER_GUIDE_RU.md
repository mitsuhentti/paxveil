# PAXVEIL

PAXVEIL проверяет Python-зависимости по официальным источникам, сохраняет отчёты и помогает выбрать обновления. Веб-приложение и Telegram-бот используют один API и одну базу проектов. Watch повторяет проверки и сообщает об изменениях, FixLab сравнивает варианты обновления, а Fire Drill ищет конкретный CVE в сохранённых проектах.

Приложение запущено и проверено локально на Windows с PostgreSQL. Исходные данные сканирования поступают из OSV, PyPI, deps.dev, FIRST EPSS и CISA KEV. Частичный ответ и неизвестные версии видны в отчёте. Отсутствие известных находок относится к проверенным версиям и доступным источникам на дату анализа.

## Что можно сделать

- Загрузить `requirements.txt`, `poetry.lock` или `uv.lock` размером до 1 MiB; выбрать Python и ОС для маркеров окружения.
- Сохранить проект, повторить проверку, открыть историю, граф и сведения об уязвимостях.
- Увидеть CVSS, датированный EPSS, сведения CISA KEV и объяснение приоритета; изменить статус обработки находки.
- Сравнить Minimal Change, Balanced и Maximum Coverage в FixLab. Целевые релизы проверяются в PyPI, метаданные разрешаются через uv, предложенные версии повторно проверяются в OSV.
- Выполнить «Проверку CVE» и различить подтверждённое совпадение, возможное совпадение, отсутствие найденного совпадения и недостаточность данных.
- Включить мониторинг Watch, настроить порог, категории, тихие часы, часовой пояс и дайджест.
- Пользоваться проектами через Telegram, связать веб-аккаунт одноразовым кодом и удалить свой проект с подтверждением.

## Работа в приложении

На странице «Проекты» нажмите «Новый проект», выберите файл зависимостей и целевое окружение. Кнопка «Создать проект и проверить» сохранит проект и запустит проверку. Отчёт появится после завершения задания.

Вкладка «Отчёт» показывает уязвимости и источники. В «Зависимостях» можно посмотреть состав проекта и граф, в «Обновлениях» сравнить варианты FixLab, в «Истории» открыть предыдущие проверки. Повторные проверки настраиваются в разделе «Мониторинг». Для поиска конкретного CVE откройте «Проверка CVE».

Чтобы связать аккаунт с Telegram, откройте «Настройки» и нажмите «Получить код». Отправьте боту `/link КОД` до истечения срока действия кода. После привязки браузер и бот покажут одни и те же проекты.

Интерфейс поддерживает светлую и тёмную темы, настольные и мобильные экраны. Новый знак PAXVEIL выполнен как геометрическая буква P; в светлой теме используется тёплый белый фон и синий акцент. Решения по оформлению описаны в [DESIGN_REVIEW.md](DESIGN_REVIEW.md).

## Быстрый запуск на Windows

Требуются уже установленные **PowerShell 7 (`pwsh`)**, Python 3.11, Node.js 24 с npm и PostgreSQL 18. Результаты проверки этой машины и официальные ссылки находятся в [AUDIT.md](AUDIT.md). Сценарий подготовки устанавливает зависимости только в каталог проекта и создаёт отдельный кластер PostgreSQL на порту 55432.

Для **новой копии** проекта откройте PowerShell 7 в каталоге `paxveil`:

```powershell
.\scripts\init.ps1
.\scripts\start.ps1
```

Полный свежий bootstrap с новым окружением и кластером через `init.ps1` ещё не выполнен целиком. Повторная подготовка существующего runtime проверена дважды: зависимости из lock-файлов, `npm ci` и production-сборка прошли; кластер и Telegram-токен сохранились. Запуск и обычная остановка вне изоляции Windows проверены. См. [операционные проверки](OPERATIONS_VALIDATION.md).

Откройте [PAXVEIL](http://localhost:3000). Описание API доступно по адресу [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Зарегистрируйте свой локальный аккаунт. Для первой проверки можно загрузить [examples/browser/requirements.txt](../examples/browser/requirements.txt): файл содержит `requests==2.31.0`, проверка не устанавливает пакет.

Токен от BotFather вставляется только в `TELEGRAM_BOT_TOKEN` локального файла `.env`. После настройки запустите приложение с ботом:

```powershell
.\scripts\stop.ps1
.\scripts\start.ps1 -Telegram
```

На текущем компьютере рабочее окружение разработки уже создано **за пределами репозитория**, в `work/runtime` рядом с `outputs`. Для него команды из каталога `outputs/paxveil` такие:

```powershell
.\scripts\stop.ps1 -RuntimeDirectory '..\..\work\runtime'
.\scripts\start.ps1 -Telegram -RuntimeDirectory '..\..\work\runtime'
```

Используйте один вариант окружения и один процесс polling. Если приложение уже запущено, открывайте его адрес; повторный старт требует остановки через соответствующий сценарий. Для повторной подготовки после остановки используйте `.\scripts\init.ps1 -RuntimeDirectory '..\..\work\runtime'`: существующие кластер и секреты сохраняются. Если в старой локальной `.env` нет поля `POSTGRES_PASSWORD` для Compose, сценарий добавит его из собственного локального адреса базы, не выводя пароль. [Подробная настройка и обновление](DEPLOYMENT.md), [Telegram](TELEGRAM.md).

## Результаты проверок

Проверка пяти зависимостей с закреплёнными версиями выявила **12 находок после объединения повторных записей об одной уязвимости**. FixLab Balanced и Maximum Coverage разрешили пять пакетов; повторная проверка предложенных версий в OSV не выявила известных уязвимостей. Minimal Change сообщил, что данных для подходящего обновления недостаточно. Результаты относятся к этому запуску и не подтверждают совместимость приложения после обновления.

Отдельный сквозной API-сценарий сохранил проект, получил три находки для `requests==2.31.0`, подтвердил совпадение `CVE-2024-35195`, сохранил Watch и проверил запрет доступа чужого владельца. Через браузер и работающий API проверены загрузка, отчёты, история, настройки и мобильная ширина 390 пикселей. Результаты проверок:

- [Итоги испытаний](TEST_RESULTS.md) и [браузерные проверки](FRONTEND_VALIDATION.md).
- [Отчёты core/FixLab](CORE_VALIDATION.json) и [API acceptance](LIVE_ACCEPTANCE.json).
- [Проверка зависимостей backend](SELF_AUDIT.json) и [npm audit](NPM_AUDIT.json).
- [Скриншоты](screenshots/) и [независимое ревью](REVIEW.md).

Токен [@PAXVEIL_Bot](https://t.me/PAXVEIL_Bot) проверен через `getMe`, polling запущен 11 октября 2026. Владелец подтвердил, что после `/start` меню появилось в Telegram; в логах два обработанных обновления. Загрузку файла, привязку, отчёт и доставку Watch ещё нужно проверить в Telegram по чек-листу [TELEGRAM.md](TELEGRAM.md). Автоматические тесты проверяют обработчики и API с подготовленными данными; записи advisory из этих тестов не используются в приложении.

## Границы анализа

Файл с отдельными пинами не устанавливает все транзитивные версии проекта. Граф показывает известные связи, а неполный состав сопровождается предупреждениями. Poetry lock без `pyproject.toml` не определяет корневые требования, поэтому FixLab сообщает об ограничении. Разрешение метаданных поддерживает x86_64; тесты пользовательского приложения и его код не запускаются. Реальная эксплуатация в конкретном приложении не определяется по одному номеру версии. Подробности: [CORE.md](CORE.md).

Мониторинг и отправка работают, пока запущен worker и доступна сеть. Локальная ссылка `localhost` открывается на этом компьютере; телефону нужен отдельно развёрнутый HTTPS-адрес. Docker Compose подготовлен, но Docker отсутствовал и контейнерный запуск здесь не выполнен. Публичный сервис и платные ресурсы не создавались.

Очередь и расписание реализованы на PostgreSQL с устойчивыми заданиями, блокировками, сроком аренды и повторными попытками. Это позволяет запускать сервис на этой машине без Redis/Celery/Airflow. ETL сохраняет историю публичных снимков, нормализует данные и проверяет качество; SQL-витрины предназначены для аналитики. Технические подробности приведены в англоязычных документах выше.

`.env`, база, пользовательские файлы и окружение исключены из Git. До публикации репозитория нужно выбрать лицензию и проверить итоговый состав файлов. До публичного сервиса нужны подтверждённые TLS, резервное восстановление, лимиты аккаунтов и правила обработки данных; см. [DEPLOYMENT.md](DEPLOYMENT.md).

Обычная остановка `stop.ps1` в финальной проверке вне изоляции Windows прошла без force-параметра. Ранее изоляция блокировала управление PostgreSQL; в этом случае сценарий сохраняет manifest и сообщает ошибку. Для проверенного проектного dev-кластера есть явный вариант `stop.ps1 -ForceDatabase` (с тем же `-RuntimeDirectory`, если он задан). Он принудительно останавливает дерево процесса; следующий запуск выполняет WAL recovery. Это fallback разработки. После финального перезапуска hash QA-проекта, одного scan, трёх статусов и подписки сохранился: [RUNTIME_VALIDATION.json](RUNTIME_VALIDATION.json).
